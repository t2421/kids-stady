## 0. いま足りないもの (現状の学習フロー)

| いま | 問題 |
|---|---|
| 呪文の習得 = 「とっくん5問 (ヒント・解説つき) → テスト10問 (8問で合格)」 | **教える段階がない**。習っていない単元 (例: 小4で わり算の ひっ算) は、いきなり問題から始まり、間違えて解説を読む しかない |
| 図つきヒントは小1の くりあがり/くりさがり (さくらんぼ図) だけ | 小2以降は文章のみ。分数・割合・速さ・角度は **絵がないと理解できない** |
| 出題の難しさは単元内で一定 | 「かんたんな形から段階的に」がない。最初の1問で挫折しうる |
| 前提単元のチェックがない | 九九ができないまま わり算に入る、通分できないまま分数の たしざんに入る |
| 「できる」の判定はテスト合格の1回だけ | 数日後に忘れていても気づけない。復習は弱点3単元のみ |
| 学ぶ動機は「呪文が欲しい」 | 世界の側から「この算数が必要だ」と迫る場面が少ない。先生役のキャラが薄い |

## 1. 目的と原則

**目的**: 小1〜小6の算数 44 単元を、学校でまだ習っていなくても、ゲームの中だけで
「理解 → できる → 忘れない」まで持っていく。ストーリーはその推進力であって飾りではない。

学習設計の原則 (小学生向けの定説に沿う):

1. **具体 → 絵 → 記号** (CPA): どの単元も、まず物や絵で見せ、次に図で考え、最後に式にする
2. **例題を見せてから、少しずつ手を離す**: 全部見せる例題 → 途中まで埋まった穴埋め → 自力
3. **小さな段階**: 1単元を 3 段階 (Lv1〜3) に割り、易しい形から確実に上げる
4. **前提を先に**: 単元には前提単元があり、前提が「できる」でなければ先に前提へ案内する
5. **間違いは診断して直す**: 誤答の型 (くりあがり忘れ、分母を足した…) を検出して、その型に合った一言を返す
6. **忘れる前に思い出す**: 合格した単元は 1日・3日・7日後に短く復習 (間隔反復)
7. **失敗は安全**: 何度でも、別の説明で、ペナルティなし。「できるようになった」ときだけ前に進む
8. **学ぶこと自体が強さになる**: レッスン・合格で経験値と物語が進む (戦闘だけが成長手段ではない)

## 2. 「できる」の定義 (単元ごとの状態)

| 状態 | 条件 | 表示 |
|---|---|---|
| まだ | レッスン未受講 | 灰 |
| れんしゅうちゅう | レッスン受講済み or テスト不合格あり | 黄 |
| できる | テスト 10問中 8問 (現状の合格) | 緑 |
| マスター | できる の後、**間隔復習 (1日・3日・7日後の 5問) を 2 回連続 4問以上** | 金 + 数晶のかけら |

- 章のストーリーゲートは「その章の **中核3単元** が できる」に統一する (現状は呪文単位で
  ばらばら)。残りの単元は任意だが、マスターで報酬 (呪文強化・メダル・かけら) がつく
- 「できる」に満たないまま先へ行く抜け道は作らない。ただし、詰まったら **別の説明** と
  **易しい段階** に戻す導線を必ず用意する (§3.4)

## 3. 教える仕組み (エンジン)

### 3.1 レッスン (単元ごとのデータ)

`src/content/lessons/<skillId>.ts` に `LessonDef` を置く (章データと同じく TS + バリデーション)。

```ts
interface LessonDef {
  skillId: string;
  title: string;                       // 「わり算 — おなじ数ずつ わける」
  prerequisites: string[];             // ["g2_kuku"]
  story: { pages: string[] };          // なぜ必要か (世界の側の困りごと、1〜3ページ)
  concept: { pages: { text: string; figure?: FigureSpec }[] };   // 絵で見せる (2〜4ページ)
  workedExample: { problem: Problem; steps: { text: string; figure?: FigureSpec }[] };
  faded: { problem: Problem; blanks: number }[];   // 途中まで埋まった穴埋め (2〜3問)
  levels: [LevelSpec, LevelSpec, LevelSpec];       // 出題の3段階 (生成器のパラメータ)
  altExplain: string[];                // 2回目に詰まったときの「別の言い方」
  mistakes: { pattern: MistakePattern; feedback: string }[];   // 誤答の型 → 一言
}
```

`FigureSpec` は §3.2 の視覚モデルを指す (`{ kind: "numberLine", from, to, marks }` など)。

### 3.3 レッスンの流れ (1単元 10〜15分)

1. **ストーリー導入** (町の困りごと。§4 の先生キャラが話す)
2. **概念ページ**: 図を見ながら 2〜4 ページ。タップで進む。声かけ口調
3. **例題**: 1問を **ステップごとに図が動いて** 解ける (見るだけ)
4. **穴埋め**: 同じ形の問題で、途中まで埋まっている。空欄だけ答える (2〜3問、ヒント常時)
5. **れんしゅう Lv1**: 3問連続正解で Lv2 へ、Lv3 まで (間違えたら段階は下がらず、
   ヒントが1段深くなる — §3.5)
6. **テスト** (既存: 10問8問)。不合格なら「別の説明 (altExplain)」→ 穴埋めからやり直し
7. **合格演出 + 経験値 + 次の復習日の予告** (「3日後に おさらいしよう」)

既存の「とっくん」は 4〜5 に統合する (「とっくんしてから テストする?」は残す)。

### 3.4 前提チェックと案内

- 単元に入る前に **前提単元から 3 問** (readiness check)。2問以上正解で進む。
  不足なら「さきに ○○ を おさらいしよう」と前提のレッスンへ (状態が できる なら省略)
- 前提グラフ (主なもの):
  - g1_add_carry ← g1_add_nc / g1_sub_borrow ← g1_sub_nc
  - g2_add_column ← g1_add_carry / g2_sub_column ← g1_sub_borrow / g2_kuku ← g1_add_nc
  - g3_div, g3_div_remainder, g3_mul_column ← g2_kuku / g3_decimal ← g2_add_column
  - g4_div_2digit ← g3_div_remainder / g4_fraction_same ← g3_fraction / g4_decimal ← g3_decimal
  - g5_fraction_diff ← g4_fraction_same + g5_multiple / g5_percent ← g5_decimal_muldiv
  - g6_fraction_muldiv ← g5_fraction_diff / g6_speed ← g5_unit_rate / g6_ratio ← g5_percent
- これは **学校で習っていない単元でも進める** ための鍵: 前提さえ「できる」なら学年を
  飛び越えて教えてよい (章=学年は物語の順序であって、学習の順序は前提グラフが決める)

### 3.5 段階つき出題・段階つきヒント・誤答診断

- **Lv1〜3 の出題**: 生成器に `level` を渡す (例: わり算 Lv1 = 九九の範囲で割り切れる /
  Lv2 = 0 を含む・答えが2桁 / Lv3 = あまりあり)。戦闘の出題は Lv2 固定、おだいは Lv3
- **ヒント3段階**: ①考え方 (「おなじ数ずつ わける と 考えよう」) → ②途中まで (図に一部
  書き込み) → ③答えの直前 (「あと 1 こ たすと?」)。間違えるたびに 1 段深く
- **誤答診断**: `makeChoices` の誤答パターン (±1 / くりあがり忘れ / 分母を足す / 位ずれ) に
  型 ID を付け、選ばれた誤答の型で一言を変える。テンキー入力でも答えの差から型を推定

### 3.6 間隔復習と毎日のおさらい

- できる になった単元は `reviewDue` (1日 → 3日 → 7日) を持つ。期日が来た単元があると
  ほこらの司祭と まなびやの先生が「おさらいの じかんだよ」と声をかける (5問・無制限)
- 4問以上で次の間隔へ、2回連続で **マスター**。3問以下なら間隔を戻し、穴埋めから短く復習
- せいせき画面に **単元マップ** (学年×単元のマス目、4色) を出す。保護者もひと目でわかる

## 4. ストーリーとの融合 (学びが物語を動かす)

### 4.1 「算数が世界を救う」を単元ごとに具体化

各単元に **町の困りごと** を1つ用意し、レッスンの導入と合格後の変化 (町が直る・道が開く)
を対にする。例:

| 単元 | 困りごと (導入) | 合格後 |
|---|---|---|
| g1_add_carry | 王都のパン屋が 8こと 5この かごを 1つに できない | パン屋が開き、やくそうが安くなる |
| g2_kuku | 九九の塔の扉が「段」を忘れて閉じた | 各階が開く (既存) |
| g3_div | 隊商の水を 人数で同じに分けられず けんかに | 隊商が出発し 砂漠の道が開く |
| g3_fraction | ピラミッドの「わけまえ」を 1/3 ずつに切れない | 盗賊王の部下が改心 |
| g4_angle | 氷の国の灯台が 角度を失い 光が届かない | 遺跡の光が通り、氷の道が溶ける |
| g5_percent | バーゲンの町の値札が消され「○%びき」がわからない | 町の店が復活、装備が割引 |
| g5_fraction_diff | ブンスウ諸島の橋が 1/2 と 1/3 でつながらない | 諸島間の橋が架かる |
| g6_speed | はやさの回廊で 速さがわからず 時間が止まる | 回廊を抜けられる |
| g6_ratio | ホシオキの地図の縮尺が壊れている | 地図が直り ゼロム城への道が見える |

(全44単元ぶんは LP-12〜17 のコンテンツ作業で埋める)

### 4.2 先生キャラクター (章ごと) と なかまが教える場面

- 各章の まなびや に **先生キャラ** を置く (章1: 王都のかんがえる ふくろう博士 / 章2: ミナトスの
  そろばん船長 / 章3: ワケーラの計算商人 / 章4: メジャーリアの はかりの女王 / 章5: パーセンの
  割合ギルド長 / 章6: ホシオキの星読み)。レッスンの語り手はこの先生
- **なかまも教える**: タスクは「たす=回復」の単元、カケルは「かける」、リトルは「単位・小数・分数」
  の単元で、レッスン中に一言ずつ口を挟む (なかまの個性 = 分野)。加入イベントの直後に
  「その なかまの得意分野」の短いレッスンが入る (加入 = 先生が増える)
- 冥王ゼロムは「数をなくす」存在。**単元をマスターするほどネガリアに色が戻る** 演出
  (章6のパレットを マスター数に応じて段階的に明るくする)

### 4.3 進行の再設計 (ゲート)

- 章の中核3単元 (例: 章3 = わり算・あまり・分数) が **できる** で章ボスへの道が開く
  (番人の hideIf を「3単元の mastery」に。フラグではなく状態を見る新しい条件式 `skill:できる`)
- 中核以外の単元は任意だが、章の **数晶は「かけら」6つ** で構成し、単元マスターで かけらが
  集まる (全部集めると章の呪文が強化・称号)。任意単元を "やらなくても進める、やると得" にする
- 学年を飛び越える子には: 前提グラフを満たせば上の章のレッスンを **ほこらの「先取り」** から
  受けられる (物語は進めない。学びだけ先に)

### 4.4 失敗の演出

- テスト不合格: 先生が「べつの言い方で もういちど」→ altExplain → 穴埋めから
- 3回不合格: なかまが登場して「いっしょに やろう」→ 前提チェックへ戻す (前提の穴が原因のことが多い)
- 全滅と同じく、責めない。「だいじょうぶ、ここから できるようになる」

## 6. 実装の前提と方針

- レッスン・視覚モデルは **データ + 純ロジック + React** で作り、Phaser は「まなびやで
  `openLesson` を発火する」だけ (既存の openSpellTest と同じ経路)
- 生成器の `level` 対応は既存の `generate(skillId, rng)` を壊さない (`generate(skillId, rng, { level })`
  の省略時 = 現状 Lv2 相当)
- 単元の状態 (`mastery`) はセーブに持ち、既存の `skillStats` から初期化できるようにする
  (既プレイヤーの合格実績を「できる」に写す)
- コンテンツ (44 レッスン) は **章 = 学年ごとにコンテンツ班へ**。1レッスン = 5〜7 ページ + 図指定 +
  例題 + 穴埋め2〜3 + altExplain + 誤答一言。Sonnet に 1 学年 (6〜8 単元) を1セッションで渡す
- すべてのレッスンはバリデーション (前提が実在・図の kind が実装済み・問題の answer が choices に
  ある・skillId 重複なし) と、E2E 1 本 (小1と小3のレッスン通し) で守る
